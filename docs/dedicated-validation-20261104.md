## 新修复与验收要求

- 草稿与检查点协议升为 4；旧草稿、模板和检查点须按原始输入重新审核，不做迁移或兼容转换。
- 预算层级未知时保留已核实组和素材，明确待澄清，不默认计划预算。
- 删除模型可写的转换参数。服务端依据字段和实际单元格选择现有受控转换；坏字段保留问题，其他合法字段保留。
- 每个实际字段所有者独立回答；保留答案的目标信息，禁止将另一素材的答案作为当前素材依据。补时区可绑定已有完整本地日期时刻。
- 删除计划字段向所有子节点广播修改的路径；模型与服务端均检查字段所有者。文件新证据与实体明确值冲突时先澄清，不能借用其他组真实单元格覆盖排期。
- 业务校验过滤无实际缺失/冲突的问题；明确消息预算冲突由服务端生成问题，并纳入预览和确认接口的阻断集合。
- 正常交互测试支持预声明的逐组、逐素材事实；原 111 组只提取 `permitted_answers` 作为正常用户事实，执行模型不得读取参考方案。

本轮新增修复尚需其自身冻结版本的 MySQL、构建、浏览器、111 组正常交互及全新 90 组三轮验收。任一错误方案可确认或其他硬门槛复现，都继续阻断生产切换。
