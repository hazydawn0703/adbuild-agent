## 通用业务能力与服务端约束

### 任务、输入范围与消息候选

任务可以在无文件、无草稿时保存意图及澄清问题。问题明确作用于任务或已有需求，普通回答只保存在当前任务，不写入项目长期默认值。

本批范围由引用用户消息的结构化选择条件表示，服务端验证后再生成选中集合。原始记录和本批需求分别处理；解析成功不等于自动纳入。“只搭建某几条”与“只修改某几条的预算”采用各自的范围语义。手动选择以当前需求 ID 绑定范围，避免刷新后再次采用过时的推断。

对话可以提出有字段来源的新增需求候选；采纳后合入同一任务的活动草稿。用户明确要求同帖多目标时，各目标保留独立需求 ID、预算和证据，不以帖子 ID 合并。新增、拆分和修改都须经服务端范围与来源验证；模型不能自行授权、确认方案或调用广告写入工具。

### 映射、检索与恢复

映射支持逐行列、固定单元格、表头及有限变换，行筛选使用受限操作，不执行模型生成的代码。金额、ID、目标、日期、时区和链接由后端统一规范化。规范值必须满足重复归一化不变；未知、冲突、数值精度丢失和日期缺少时刻保持显式问题。

R1 暴露的映射契约错误已纳入后续通用修复：提议阶段对实际工作簿执行完整来源校验，字段同时出现在列与绑定、固定来源缺少单元格等问题在有界结构修正中处理，不能等到人工确认时才首次发现。

服务端可按任务明确的选择词和 ID 检索整个工作簿，为模型提供有界的命中行、附近行及表头证据。目标位于第 100 行之后也应能被检索；覆盖不足必须报告实际范围，不能声称完整检查。

区域补读使用明确页面、覆盖量和游标，每页实际读取不超过 1,000 格。已读证据、文件指纹及未完成范围保存于任务分析记录；恢复先读取下一页，重复已读区域且没有进展时返回待办。超过本轮时间、上下文或补读预算时保留产物，不静默截断后宣称成功。私密授权材料不进入保存给模型的证据内容。

平台信息可以来自明确映射、审核过的过滤条件对应单元格或可验证的 TikTok 链接，并保留来源。未知平台不能因为同一工作簿存在 TikTok 记录就默认成为 TikTok。

### 字段证据与历史匹配

每项关键字段建议须得到明确任务消息、适用且已确认的项目默认值、已有核实字段或精确历史引用支持。引用存在不等于引用内容支持该值。历史采纳会重新核对项目文件归属、原文件指纹、来源行和规范化值，保留历史出处，再增加采纳人及时间。

历史检索先由服务端限定租户、项目和账户。候选分别显示帖子／业务编号匹配证据、账户是否已证实、排期是否可比较、配置差异、原始来源和参考用途。同帖不同目标、明确不同排期不会直接去重；仅业务编号相同、账户不明或时间无法比较时保留待核实，不认定为已存在投放。历史的计划预算和广告组预算分别保留和比较。

### 三层结构与人工确认

`BuildDraft` 继续是规范化业务配置的唯一来源，内部保存计划、广告组和广告的真实父子关系。默认一项独立需求生成一套结构；多目标、受众分组及预算分配须有明确依据或可审核提案。预算作用层、币种、类型、比例、舍入和合计由后端校验。

映射审核、提案采纳和完整方案确认互相独立。人工确认绑定服务端草稿版本及摘要；字段、范围、结构或授权变化使原确认失效。平台能力、受众与素材权限仍显示未核实，不能因配置齐全而变为可真实投放。

前端沿用三栏工作台和 AG-UI 状态交互，使用 `@ag-ui/client` 连接现有服务端。移除没有承担本项目流程职责的 Provider 与依赖，避免额外运行时、远程 Provider 配置或构建负担。任务、问题、提案、版本冲突和确认有效性以服务端状态恢复。

AG-UI 外层图使用官方库的、每个 HTTP 请求独立的内存 checkpointer，仅承载当前传输帧；范围、字段和可恢复业务流程仍由任务表及内层 MySQL checkpoint 保存。传输图不保存另一份可编辑配置。线程由服务端租户、任务和请求 ID 确定，不采用浏览器传入的线程或权威状态。真实 SSE 测试覆盖提案采纳、错误隔离及人工确认，避免仅用 `/chat` 测试替代实际前端接口。

## 已知读取与业务边界

H1/H2 所属样式异常类别仍超出当前 openpyxl 主解析路径的读取能力。读取器保持单一路径；不修改原工作簿、不清空样式、不按特定文件修补，也不引入静默备用读取器。已检查的 python-calamine Python 接口无法满足本项目同时读取公式、缓存缺失状态、超链接及单元格格式的契约，因此没有直接替换或额外加入该包。

这类错误现在可诊断、可重新导出后恢复，但仍应统计为文件未解析，不能算方案理解成功。H2 的安装目标另外超出本轮涨粉、视频观看、流量三类目标的范围；应明确说明不支持，不能替换为流量以提高得分。

原始样例的历史排期保持原值。过期排期不得自动平移至今天；正确阻断过期排期与正确理解广告方案分别计分。

## 部署与重新冻结

真实执行开关持续为关闭，Worker 在读取或领取广告队列之前退出；部署后仍须核对 Worker 停止且禁用。映射、编辑、提案采纳和方案确认均不得增加执行批次、广告部署、队列任务或预算预占。测试中的广告接口一旦被调用即失败。

最终冻结在开发、实际验收和部署检查完成后生成，记录真实合并 commit、完整受控源码及构建／依赖清单、提示词与归一化规则摘要、模型配置与实际返回标识、时间基准、重试和澄清上限，以及运行驱动、评分适配与协议。当前冻结程序逐文件覆盖 `backend`、`frontend`、`deploy`、`docs` 和 `scripts`；私密输入、原始输出及运行协议各自另外封存并关联运行 ID，不放入公开仓库。

供应商模型别名可能更新底层实现，该限制必须随冻结记录披露。七组及其变体的修复后成绩始终标为回归／复测。新的独立泛化结论只能来自重新冻结后接收的新未见材料，参考答案不得进入模型输入。
